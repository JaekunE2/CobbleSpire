# CobbleSpire (가제) 기획서 v0.1

작성 2026-11-10. 코블버스(COBBLEVERSE 1.7.42, Cobblemon 1.7.3, MC 1.21.1 Fabric) 위에서 돌아가는 **슬레이 더 스파이어식 로그라이크 덱빌딩 모드**. 스타터 포켓몬 하나를 골라 무작위 지도를 올라가며, Cobblemon·Showdown 전투 대신 **기술 카드 + 에너지 코스트** 전투를 새 인터페이스로 진행한다.

CobbleLeague·CobbleSynergy와 같은 저장소 구조(Fabric Kotlin, 서버 권위, JSON 데이터)로 만들고, 둘과 **함께 설치해도 충돌하지 않는 독립 모드**로 둔다.

## 1. 슬레이 더 스파이어는 어떤 게임인가

2019년 Mega Crit의 로그라이크 덱빌딩 게임. 한 판(런)은 30~60분이고, 죽으면 처음부터다. 핵심 루프는 다음 여섯 가지다.

| 요소 | 슬더슬 | 핵심 재미 |
|---|---|---|
| 캐릭터 | 4명, 각자 고정 시작 덱(공격 5·방어 4·고유 1)과 시작 유물 | 캐릭터마다 덱 아키타입이 다르다 |
| 지도 | 막(Act) 3개, 막마다 15층, 층마다 노드 2~4개 중 하나로 이동. 노드 종류: 일반 전투·엘리트·이벤트(?)·휴식·상점·보물·보스 | 경로 선택이 곧 리스크 관리 |
| 전투 | 매 턴 에너지 3, 카드 5장 드로우, 턴 끝에 손패 전부 버림. 카드는 공격/스킬/파워, 코스트 0~3. 방어도는 턴마다 사라짐. 적은 다음 행동(의도)을 미리 보여줌 | 정보가 공개된 퍼즐 |
| 보상 | 전투 후 골드 + 카드 3장 중 1장(거절 가능) + 가끔 포션. 엘리트는 유물. 보스는 희귀 유물 3택1 | 덱을 키우는 것보다 **안 넣는 것**이 중요 |
| 휴식 | 회복 30% 또는 카드 1장 강화 | 자원 트레이드오프 |
| 메타 | 죽어도 카드·캐릭터 해금, 승천(난이도 1~20), 일일 도전, 시드 공유 | 반복 플레이 동기 |

상태 효과는 힘(공격 +N), 민첩(방어 +N), 취약(받는 피해 ×1.5), 약화(주는 피해 ×0.75), 허약, 독(턴마다 피해) 정도로 **적고 단순**하다. 카드 200여 장, 유물 170여 개, 이벤트 50여 개가 콘텐츠의 전부다.

## 3. 게임 디자인

### 3.1 한 판(런)의 구조

- 3막 × 각 15층 + 최종 보스. 목표 플레이 시간 40~60분.
- **1막 "풀숲과 숲길"**: 야생 1~2마리, 보스 = 체육관 관장(이슬·마티스·민화 중 랜덤).
- **2막 "동굴과 산"**: 야생이 세지고 트레이너 등장, 보스 = 상위 관장(독수·초련·강연).
- **3막 "포켓몬 리그"**: 보스 = 사천왕 1명(이향·목호·윤진·강석·가을·미첼 중) → 승리 시 **챔피언**(목호·성호·난천·카르네·단델 중 랜덤).
- 막마다 보스 전 휴식 노드는 보장. 막 사이에 **진화 선택** 기회(3.9).
- 체력(HP)은 런 내내 이어지며, 포켓몬센터·열매·일부 도구로만 회복한다.

### 3.2 시작: 스타터 선택

- 처음 해금된 스타터 3마리(불·물·풀, 예: 파이리·꼬부기·이상해씨)에서 1마리. Cobblemon 스타터 선택 화면 틀을 재사용한다.
- 스타터마다 **시작 덱 10장 + 특성 패시브 + 시작 열매 1개**.
- 예: 파이리(특성 맹화 = HP 1/3 이하일 때 불꽃 카드 피해 +50%)
  - 할퀴기 ×4 (0.. 공격, 1코, 6 피해)
  - 방어 ×3 (트레이너 카드, 1코, 방어 5)
  - 불꽃세례 ×1 (공격, 1코, 6 피해, 10% 화상)
  - 울음소리 ×1 (기술, 1코, 상대 공격 -1)
  - 응원 ×1 (트레이너 카드, 0코, 카드 2장 드로우, 소멸)
- 스타터 라인업은 메타 진행으로 확장(3.11): 관동 → 성도 → 호연 … 스타터 + 이브이·피카츄 같은 특수 스타터.

### 3.3 파티와 덱: 1마리로 시작해 최대 3마리

슬더슬은 1캐릭터지만 포켓몬의 정체성은 "팀"이다. 둘을 이렇게 합친다.

- 파티 최대 3마리. **앞에 나온 1마리만 피해를 받고 카드를 쓴다.** 나머지는 벤치.
- 덱은 **파티 공용** 1개. 카드마다 "소유 포켓몬" 표시가 있고, **그 포켓몬이 앞에 있을 때만 자속(STAB) 보정**을 받는다. 다른 포켓몬이 앞에 있어도 카드는 쓸 수 있다(트레이너가 지시하는 개념).
- 교체: 트레이너 카드 "교체"(1코, 벤치 포켓몬과 바꾸고 1장 드로우) 또는 턴 시작 때 무료 교체 1회(배지 난이도에서 제거). 앞 포켓몬이 쓰러지면 벤치가 자동으로 나온다. **파티 전원이 쓰러지면 런 종료.**
- 동료 영입: 야생 전투 후 포획(3.10), 이벤트(알·교환·낚시). 영입하면 그 포켓몬의 레벨업 기술 3장이 덱에 들어오고 이후 카드 보상 풀에 그 포켓몬의 학습 기술이 섞인다.
- MVP(1단계)는 **1마리 고정**으로 만들고, 벤치·교체는 2단계에 켠다. 엔진은 처음부터 파티 구조로 짠다.

### 3.4 전투 규칙

**턴 구조**

1. 턴 시작: 에너지 3 회복, 카드 5장 드로우, 방어 0으로 초기화, 지속 효과(날씨·필드·독·화상) 처리.
2. 플레이어: 카드를 원하는 만큼 사용. 적의 **의도**(다음 기술의 타입·분류·예상 피해)는 항상 표시.
3. 턴 종료: 남은 손패 버림(보존 카드 제외). 적이 의도대로 행동. 우선도 +1 이상 기술은 플레이어 턴 "전"에 끼어든다(선제공격은 특수 연출).
4. 덱이 비면 버린 더미를 섞어 새 덱.

**수치(초안, 전부 JSON에서 조정)**

- 플레이어 포켓몬 HP = 종족값 HP + 50 (파이리 89, 꼬부기 94, 이상해씨 95). 진화하면 차이만큼 최대 HP 상승.
- 카드 피해 = round(위력 × 0.15) → 할퀴기 6, 화염방사 14, 파괴광선 22.
- 공격 쪽 보정 = 1 + 0.1 × (공격 종족값 − 50)/10 … 처럼 종족값이 미세하게 반영. 물리는 공격, 특수는 특공. 상대의 방어·특방도 같은 식(±20% 범위로 억제).
- **자속** ×1.25. **타입 상성** 효과 굉장함 ×1.5, 별로 ×0.67, 효과 없음 ×0.25(카드가 완전히 죽지 않게). Cobblemon `ElementalTypes` 상성표 사용. 수치는 플레이테스트 후 ×2/×0.5로 올릴지 결정.
- 랭크: 공격·특공 +1당 주는 피해 +25%, 방어·특방 +1당 받는 피해 −20%(최대 ±3으로 제한). 스피드 +1당 턴 시작 드로우 +1장(최대 +2) → 스피드를 "손패 크기"로 번역.
- 방어: 그 턴 받는 피해를 흡수, 턴 끝에 소멸. "방어"(Protect) 카드 = 방어 5, 철벽 = 방어 +1랭크 영구…와 같이 기술마다 다르게.

**상태이상(슬더슬 6개에 대응, 전부 전투 종료 시 해제)**

| 상태 | 효과 | 슬더슬 대응 |
|---|---|---|
| 독 | 턴 시작에 스택만큼 피해, 스택 −1 | 독 |
| 맹독 | 턴마다 스택 +1 (피해 증가) | 강화 독 |
| 화상 | 턴 시작 2 피해, 물리 피해 −25% | 약화 |
| 마비 | 에너지 −1 (해당 턴) · 스피드 랭크 무효 | 허약 |
| 잠듦 | 2턴간 드로우 −2, 피격 시 해제 | 기절(완화) |
| 얼음 | 1턴 행동 불가, 불꽃 피격 시 해제 | 완전 봉쇄는 1턴 한정 |
| 취약(포켓몬풍 이름 "허점") | 받는 피해 ×1.5 | 취약 |

**날씨·필드 = 파워 카드**: 쾌청(불꽃 ×1.5, 물 ×0.5, 3턴), 비, 모래바람(바위 특방↑), 설경, 일렉트릭필드·그래스필드·사이코필드·미스트필드. 리플렉터·빛의장막·순풍·독압정·스텔스록도 기술 카드로 들어온다(CobbleSynergy가 이미 같은 기믹을 정리해 둠).

**특성 = 패시브**: 맹화·급류·심록(HP 1/3 이하면 해당 타입 +50%), 위협(전투 시작 시 상대 공격 −1), 정전기(접촉 피격 30% 마비), 가속(턴마다 스피드 +1), 자연회복(교체 시 상태이상 해제), 마이페이스·방진… 종 특성 중 **구현한 것만** 쓰고 나머지는 "효과 없음(미구현)"으로 표시. 60개 정도면 스타터·주요 야생이 다 덮인다.

### 3.5 카드 시스템

**기술 카드 자동 생성**(tools/card_census.py로 확인함, 부록 A)

Showdown 952개 중 Z·다이맥스·비공식 114개를 빼면 **821개**가 한국어 이름·설명과 함께 변환된다. 그중 **522개는 위력·분류·부가효과만으로 자동 변환**되고, 299개(방어·씨뿌리기·빛의장막처럼 콜백 로직이 있는 것, 위력 가변기, 일격기)는 수동 정의가 필요하다. MVP는 자동 522개 중 **밸런스를 본 150장 + 수동 50장**으로 시작하고, 나머지는 "미검증" 플래그로 풀에서 뺀다.

| 분류 | 생성 규칙 |
|---|---|
| 공격(물리/특수) | 피해 = 위력×0.15. 코스트: 위력 ≤45 → 1(선제공격·전광석화처럼 우선도 >0이면 0), 46~95 → 2, 96 이상 → 3. 반동기는 −1코 |
| 변화(상태) | 1코 기본. 랭크 +2 기술(칼춤·나쁜음모)은 2코, 자신 회복(HP회복)은 2코 + 소멸 |
| 부가효과 | 10%/30% 확률은 그대로 확률(슬더슬엔 없지만 포켓몬다움 유지). 100%는 확정 |
| 충전기(솔라빔) | 사용 턴에 피해 없음 + 다음 턴 자동 발동 | 
| 재충전기(파괴광선) | 다음 턴 에너지 −1 |
| 연속기(연속자르기) | 2~5회 → 고정 3회로 단순화 |
| 교체기(유턴·볼트체인지) | 피해 후 교체(파티 2마리 이상일 때만 등장) |
| 소리·접촉 플래그 | 특성(방음·정전기)과의 상호작용만 |

**트레이너 카드**(포켓몬이 아니라 트레이너가 쓰는 카드, ~20장, 전부 신규 정의)

방어(1코, 방어 5) · 응원(0코, 2장 드로우, 소멸) · 교체(1코) · 몬스터볼 던지기(2코, 야생 전용 포획 시도) · 상처약(1코, HP 20, 소멸) · 작전 지시(0코, 다음 공격 카드 +50%) · 후퇴(0코, 방어 3 + 교체) · 기술머신 임시 사용(X코) 등. 포켓몬 TCG의 트레이너 카드 느낌.

**희귀도**: 일반(레벨업 초반 기술) / 희귀(레벨업 후반·기술머신) / 전설(알기술·전용기·사천왕 보상). 보상 풀 확률 65/30/5%.

**강화(+)**: 휴식 노드 "훈련" 또는 기술머신 상점. 기본 규칙 = 피해 +3 또는 코스트 −1 또는 부가효과 확률 ×2, 기술마다 JSON으로 지정. 이름은 "화염방사+"가 아니라 **"화염방사 (숙련)"** 처럼 포켓몬풍.

### 3.8 지도와 이동 선택지

- 슬더슬과 같은 15층 그래프(시작 2~4갈래, 층당 노드 3~5개, 합류·분기). 7층 보물, 보스 직전 휴식은 고정.
- **표현은 "루트 지도"**: 노드가 "1번도로 → 상록숲 → 월견산"처럼 지명을 달고, 노드 아이콘은 풀숲(야생)·트레이너(눈 마주치는 트레이너)·물음표(이벤트)·포켓몬센터·프렌들리숍·보물상자·배지(관장). 위로 올라가는 탑 대신 **지방을 가로지르는 길** 느낌.
- 이동 선택지 텍스트도 포켓몬풍: "풀숲을 헤쳐 간다(야생 포켓몬이 튀어나올 것 같다)", "트레이너의 시선이 느껴진다(눈이 마주치면 대전!)", "무언가 반짝인다".
- 노드 비율(막당): 야생 45% · 트레이너 15% · 이벤트 22% · 휴식 12% · 상점 5% · 보물 1(고정). 1막 1~5층엔 트레이너 없음.
- 2단계 아이디어(월드 연동): 막마다 `cobbleleague:league` 차원 안 작은 방으로 이동하고, **다음 노드가 문 2~3개**로 나타나 걸어서 고르는 식. 1단계는 2D 지도 화면만.

### 3.11 적 설계

- **야생**: 막별 등장 테이블을 Cobblemon 종 JSON의 `labels`(gen, legendary 등)와 CobbleLeague `Rarity`로 자동 생성. HP = 종족값 HP × 막 계수(1막 0.8, 2막 1.2, 3막 1.6). 의도 패턴은 레벨업 기술 4개 중 가중 순환(공격 2 → 변화 1 → 강한 공격). 2마리 야생은 1막 후반부터.
- **트레이너**: 포켓몬 2마리 연속(1마리 쓰러지면 다음). 패턴이 더 공격적이고 도구를 쓴다.
- **관장·사천왕·챔피언**: CobbleLeague `creep/*.json` 로스터 중 3마리를 쓰고, 관장마다 **기믹**이 하나씩: 이슬(비 상시), 마티스(일렉트릭필드·마비), 민화(씨뿌리기·가루), 독수(독압정·맹독), 초련(리플렉터·트릭룸=의도 역순), 강연(쾌청·화상), 사천왕은 두 기믹 조합, 챔피언은 파티 6마리 중 3마리 교체 사용.
- 전투 길이 목표: 야생 3~5턴, 트레이너 6~9턴, 보스 10~15턴.

### 3.12 메타 진행 (서버 플레이어별 저장)

- **스타터 해금**: 1막 클리어마다 새 지방 스타터 1세트, 챔피언 클리어 시 이브이·피카츄·꼬마돌 같은 변칙 스타터.
- **배지 난이도 0~8**: 1 적 HP +10%, 2 무료 교체 없음, 3 엘리트 증가, 4 시작 HP −10, 5 상점 가격↑, 6 보스 기믹 강화, 7 열매 2개 제한, 8 챔피언 6마리 전원.
- **도감**: 런에서 본/잡은 종을 기록 → 일정 수마다 카드 풀·이벤트 해금.
- **오늘의 던전**: 날짜 시드 공유, 서버 친구끼리 점수(층·보스·남은 HP·턴 수) 비교. CobbleLeague 로비 화면에 순위 패널 1개 추가.
- 기록: 런 결과 JSON(덱·도구·사망 원인) 저장, "지난 런 보기" 화면.

## 5. 기술 설계

```
cobblespire/
  src/main/kotlin/dev/cobblespire/
    engine/      순수 Kotlin, MC 의존 없음: RunState, MapGen, Battle, Cards, Effects, Relics, Events, Rng(시드)
    data/        JSON 로더: cards.json, trainer_cards.json, relics.json, berries.json, events.json, encounters.json, bosses.json, abilities.json
    server/      SpireService(플레이어별 Run 보관·틱·저장), 패킷 핸들러, 명령 /spire, 메타 저장(플레이어별 json)
    client/      SpireClient(키·패킷), 화면 10개, SpireSkin(텍스처 9분할), CardWidget, PokemonPortrait
  src/main/resources/data/cobblespire/…json, assets/cobblespire/textures/gui/(새 리소스 ~20장), lang/ko_kr.json
  tools/        card_census.py(있음) → gen_cards.py(Showdown→cards.json), balance_sim.py(자동 플레이 1,000런 통계)
  src/test/     엔진 단위 테스트(전투 공식·지도 생성·시드 재현·이벤트 분기), 자동 플레이어로 1막 완주 테스트
```

- **서버 권위**: 모든 판정·난수는 서버. 클라이언트는 상태 스냅샷(JSON)을 받아 그리고, 행동(카드 사용·대상·노드 선택·선택지)만 보낸다. CobbleLeague `LeaguePayload`와 같은 JSON 패킷 1종 + revision 번호.
- **저장**: 런 상태는 매 행동마다 `world/cobblespire/runs/<uuid>.json`에 기록 → 접속 끊겨도 이어하기. 메타는 `meta/<uuid>.json`.
- **시드**: 런 시드 하나로 지도·보상·이벤트·적 패턴 전부 재현(오늘의 던전·버그 재현용).
- **포켓몬 실체**: 런 중 파티는 `Pokemon` 객체(종·특성·진화 판정용)로 들고 있되 **플레이어 실제 파티/PC는 건드리지 않는다**. 클리어 보상으로 "런의 스타터를 실제로 받기"는 선택 옵션(서버 설정).
- **전투 비주얼 1단계**: 전체 화면 `Screen` + `drawProfilePokemon`. 2단계: 리그 차원 방에서 실제 `PokemonEntity` 2마리를 세워 두고 카드 사용 시 `ActionEffects` 타임라인 재생(가능성 검증 필요).
- **호환**: Cobblemon 1.7.3 API만 사용, CobbleLeague·CobbleSynergy는 `modCompileOnly` 없이 독립. 둘이 설치된 서버에서 키·HUD 겹침만 확인.

- **월드 연동 연출(2단계)**: `ActionEffects`가 `BattlePokemon` 컨텍스트를 요구해 전투 밖 재생이 불확실. 실패해도 1단계 화면으로 성립.

- 파일: `proto/cobblespire-proto.html` (원본 `proto/src.html` + `_moves_ko.json` → `_build.py`). 발행 링크: https://claude.ai/artifact/H1Ly6nam2DrKrrpFvgHmSS

- 제목 화면에서 **교체형 / 동시형**과 **상성 배율(완화 / 원작)** 전환.
- 두 방식의 차이(체험판 구현):

| | 교체형 | 동시형 |
|---|---|---|
| 필드 | 앞 1마리, 벤치 2 | 최대 3마리 전부 |
| 카드 | 누구 기술이든 사용, 자속은 앞 포켓몬 | 소유 포켓몬이 살아 있어야 사용, 자속은 소유자 |
| 교체 | 턴당 무료 1회 + 교체·후퇴 카드 | 없음 |
| 적 | 단독·순차 | 2마리 동시 흔함(파티 수에 비례), HP +15% |
| 적 표적 | 앞 포켓몬 | HP 낮은 쪽 50% |

- 밸런스는 `proto/_sim2.js`의 봇(공격 우선·HP 30% 이하면 교체)으로 150런씩 돌려 **두 방식 모두 승률 약 65%, 사망의 80%가 관장전**이 되도록 적 HP·피해 배율(`BAL`)을 맞췄다. 교체형은 벤치 HP가 모두 쓰이므로 적 피해 배율이 더 높다(관장 2.0 vs 1.2).
- v0.2 (11-10 저녁): 포켓몬은 5세대 애니메이션 스프라이트(PokeAPI, 앞·뒤)와 도구·열매·볼 아이콘을 임시로 넣었다(실제 모드는 Cobblemon 3D 모델·아이템 텍스처). 전투 연출: 타입 색 버스트, 피해·회복 숫자, 상태이상·랭크 말풍선, "효과가 굉장했다!", 흔들림·쓰러짐, 날씨(비·모래바람·쾌청) 아레나, 몬스터볼 흔들림, WebAudio 합성 효과음(끄기 가능). 적 턴은 한 마리씩 순차 연출. 제목의 **자동 시연**과 상단 **자동** 버튼으로 봇이 플레이하는 시뮬레이션을 볼 수 있다. 헤드리스 Chromium(Playwright, `proto/_pwdemo.py`)으로 두 방식 모두 오류 0으로 확인. 화면 샘플은 `proto/shots/`.
- 체험 후 결정할 것: 교체형 vs 동시형, 전투가 끝나면 쓰러진 포켓몬이 HP 20%로 일어나는 규칙, 포획 성공률 공식(0.15 + 0.75×포획률×(1−남은 HP 비율)).

## 10. 멀티플레이 설계 초안 (2026-11-11, 체험판 v0.3에 구현)

실제 모드에서는 서버의 다른 플레이어가 들어오는 자리를 체험판에서는 **봇 동료**(각자 파티·덱·돈·볼·열매·도구를 따로 가짐)로 채워 둘 다 시험할 수 있게 했다. 제목 화면에서 인원(1~4)과 방식, 적 강도(자동/인원 비례/고정)를 고른다.

### 10.1 공통 구조: 지역 단위 동시 진행

- 지도는 하나, 위치는 플레이어마다. 모두가 같은 "열"(지역)에 있을 때만 다음 열로 넘어간다(슬레이 더 스파이어 2 협동과 같은 락스텝).
- 같은 노드를 고른 플레이어끼리 한 그룹. 그룹이 전투 노드면 **협동 전투**, 비전투 노드(이벤트·센터·상점·보물)는 각자 처리.
- 협동 전투: 적은 하나의 무리, 참가자는 각자 에너지 3·손패 5·덱·버림 더미를 가진다. 턴 순서는 "나 → 동료들 → 적". 적의 의도는 모든 참가자의 필드 포켓몬 중에서 표적을 고른다(HP 낮은 쪽 50%). 참가자 전원의 포켓몬이 쓰러져야 패배. 자기 포켓몬이 다 쓰러진 참가자는 남은 턴을 건너뛰고, 승리하면 HP 20%로 일어난다.
- 내가 없는 그룹은 같은 엔진으로 봇이 즉시 처리(헤드리스)하고, 결과가 지도의 "동료 소식"에 한 줄씩 뜬다(예: "민수: 월견산 기슭 야생 나옹·피카츄 승리 (HP 8/3, 카드 연옥, 포획 실패)").
- 체육관(마지막 열)은 노드가 하나라 전원이 자동으로 합류한다. 관장은 항상 인원 비례로 강해진다.

### 10.2 투표형 — 한 팀으로 이동

- 노드마다 각자 1표. 다수결, 동률은 무작위. 봇은 파티 HP·돈·포획 여부로 표를 정하고, 사람이 고르기 전에 봇의 표가 지도에 보인다(반투명 트레이너 말).
- 전투는 항상 전원 협동. 적 강도는 인원 비례(아래 표). 보상은 각자 전부(카드 3택1, 돈, 도구, 포획 기회는 참가자 중 1명에게 무작위).
- 느낌: 늘 같이 다니므로 가장 "협동 게임"답다. 결정이 투표라서 한 명이 끌고 가기 어렵다.

### 10.3 분산형 — 따로 또 같이

- 각자 길을 고른다. 같은 노드면 함께 싸우고, 다르면 따로 싸운다. 봇의 선택이 먼저 보이므로 사람이 합류할지 흩어질지 정한다(지도 버튼에 "민수·유리와 함께 · 보상 1/3" / "혼자 · 보상 전부" 표시).
- 적 강도는 **고정**(혼자 가도, 셋이 가도 적은 같다). 대신 함께 싸우면 **돈 1/n, 카드 선택지 3장 → 2장, 도구·열매·포획 기회는 1명에게만**. 혼자 가면 전부 가진다.
- 관장만 인원 비례. 그래서 길에서 흩어져 보상을 모은 뒤 체육관에서 합류하는 흐름이 된다.
- 느낌: "흩어질까, 뭉칠까"가 매 지역의 선택이 된다. 서로 다른 노드를 보고 오므로 소식 공유가 재미 요소.

### 10.4 적 강도 계수 (`COOP`, 인원 1명 추가당 증가율)

| 파티 방식 | 야생 (마리 수도 인원만큼) | 트레이너 | 관장 |
|---|---|---|---|
| 교체형 | HP +35%, 피해 +18% | HP +85%, 피해 +45% | HP +90%, 피해 +45% |
| 동시형 | HP +55%, 피해 +30% | HP +130%, 피해 +70% | HP +170%, 피해 +90% |

동시형은 참가자마다 필드가 3마리라 표적이 분산되어 계수가 더 크다.

### 10.5 봇 시뮬레이션 결과 (`proto/_sim3.js`, 사람 자리도 봇, 30런씩)

| | 2인 교체형 | 2인 동시형 | 3인 교체형 | 3인 동시형 |
|---|---|---|---|---|
| 투표형 승률 | 77% | 80% | 50% | 73% |
| 분산형 승률 | 83% | 73% | 93% | 80% |

사망은 거의 전부 관장전. 분산형은 길에서 흩어지는 만큼 봇이 중간에 쓰러지는 경우가 드물게 있다(런당 0~0.07명). 혼자 플레이(65%)보다 협동이 쉬운 편이라 실제 모드에서는 관장 계수를 더 올리거나, 투표형 3인 교체형처럼 낮은 조합은 계수를 낮추는 식으로 조합별 미세 조정이 필요하다.

### 10.6 실제 모드에서의 구현 메모

- 런 상태를 "런(지도·열) + 플레이어 상태(파티·덱·돈·위치)"로 나눈 구조를 그대로 서버 측 데이터로 옮기면 된다. 체험판의 `S.multi.players[]`가 플레이어 상태, `battle.pl[pid]`가 협동 전투의 참가자별 손패·에너지.
- 협동 전투의 턴 순서는 체험판처럼 순차(한 사람씩)가 구현이 쉽고, 동시 입력은 "모두 턴 종료를 누르면 적 턴"으로 바꾸면 된다.
- 투표·그룹 편성·동료 소식은 패킷 3개(투표, 노드 확정, 결과 요약)면 된다.
- 결정할 것: 두 방식 중 하나만 갈지 서버 설정으로 둘 다 둘지, 분산형에서 중간에 쓰러진 플레이어의 처리(관전 / 체육관에서 HP 1로 합류 / 런 탈락).
